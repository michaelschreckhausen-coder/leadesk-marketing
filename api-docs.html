Binde Leadesk per REST-API an — Kontakte, Deals, Unternehmen, Content und Reports lesen und schreiben. Authentifizierung über API-Key oder OAuth2, jede Anbindung ist auf ein Team beschränkt.

Basis-URL & Format

Alle Endpoints liegen unter der Versionsbasis /v1:

https://supabase.leadesk.de/functions/v1/public-api

Anfragen und Antworten sind JSON. Erfolgreiche Antworten liefern die Nutzdaten unter data, Fehler immer im Format { "error": { "code", "message", "details" } }. Breaking Changes erscheinen nur unter einem neuen Präfix (/v2); /v1 bleibt stabil.

Authentifizierung

Zwei Verfahren werden unterstützt. Jedes Credential gehört zu genau einem Team und sieht ausschließlich dessen Daten.

API-Key erhalten: API-Zugänge werden aktuell von Leadesk bereitgestellt. Fordere deinen Key über support@leadesk.de bzw. deinen Ansprechpartner an — ein Self-Service in den Konto-Einstellungen folgt.

API-Key

Übergib den Key in einem der beiden Header:

X-API-Key: lk_live_xxxxxxxx
# oder
Authorization: Bearer lk_live_xxxxxxxx

OAuth2 (Client-Credentials)

Für Integrationspartner. Tausche client_id + client_secret gegen einen kurzlebigen Access-Token (1 Stunde):

curl -X POST "https://supabase.leadesk.de/functions/v1/public-api/v1/oauth/token" \
  -H "content-type: application/json" \
  -d '{"grant_type":"client_credentials","client_id":"lk_client_...","client_secret":"lk_secret_..."}'

# Antwort:
# { "access_token": "lk_at_...", "token_type": "Bearer", "expires_in": 3600, "scope": "..." }

Danach: Authorization: Bearer lk_at_...

Scopes

Jedes Credential trägt Scopes, die Lesen/Schreiben pro Ressource freischalten. Fehlt der passende Scope, antwortet die API mit 403.

contacts:read · contacts:write · companies:read · companies:write · deals:read · deals:write · content:read · content:write · reports:read

Endpoints & Beispiele

Kontakte

GET/v1/contactsListe (Filter: q, status, limit, offset)
POST/v1/contactsKontakt anlegen
GET/v1/contacts/{id}Kontakt abrufen
PATCH/v1/contacts/{id}Kontakt aktualisieren
DELETE/v1/contacts/{id}Kontakt löschen
# Kontakt anlegen
curl -X POST "$BASE/v1/contacts" \
  -H "X-API-Key: $KEY" -H "content-type: application/json" \
  -d '{"first_name":"Anna","last_name":"Müller","email":"anna@acme.de",
       "company":"ACME","lead_source":"website","status":"new","tags":["inbound"]}'

# Liste mit Filter
curl "$BASE/v1/contacts?status=connected&limit=50" -H "X-API-Key: $KEY"
Hinweis zu status: Das API-Feld status nutzt das Vokabular unten (new, connected, …). Die interne deutsche Qualifizierungsstufe (Lead/LQL/MQL/MQN/SQL) kommt in Antworten zusätzlich als read-only Feld qualification zurück.

Beim Schreiben werden nur bekannte Felder übernommen, alles andere wird ignoriert. Ein ungültiger Enum-Wert führt zu 422.

Rate-Limits & Pagination

Standard-Limit: 120 Anfragen pro Minute je Credential. Jede Antwort trägt die Header X-RateLimit-Limit, X-RateLimit-Remaining und X-RateLimit-Reset (Unix-Sekunden). Bei Überschreitung: 429.

Listen-Endpoints paginieren über limit (Standard 50, max 200) und offset. Die Antwort enthält pagination: { limit, offset, total }.

Die vollständige Maschinenbeschreibung liegt als OpenAPI 3.1-Spezifikation bereit und lässt sich direkt in Postman, Insomnia oder Codegen-Tools importieren.
